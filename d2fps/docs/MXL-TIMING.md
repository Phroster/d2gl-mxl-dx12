# Source integration of the accepted MXL timing fix

Base: Jarcho/d2-rs `177fb5a9d723005ca7fc6c084330997d8c15df51`.

This fork implements the D2FPS clock selection and realm prediction in Rust, with four guarded D2Client operand patches to keep the client timestamps consistent. The implementation is in `d2fps/src/mxl_timing.rs`, with native tests in `d2fps/src/mxl_timing_tests.rs`.

## Why changing only the pictured branch is insufficient

`update_game_time()` in `d2fps/src/hooks.rs` reads the local server's timestamp in SP and the client's `last_update` in other modes. Upstream reads `timeGetTime() & 0x7fffffff` for SP and `GetTickCount()` otherwise. Changing the latter alone would pair a new clock read with timestamps still generated by the old client clock.

The fork changes the client producer first, then selects the matching consumer clock. If the producer patches fail, the consumer remains on its upstream clock. It also applies the realm-only prediction extension described below.

## Exact changes

| Location | Integration |
|---|---|
| D2Client RVA `0x44A81` | Client step timestamp: preserve `mov esi,[IAT]`; redirect its operand |
| D2Client RVA `0x44B7C` | Paused update timestamp: preserve `call [IAT]`; redirect its operand |
| D2Client RVA `0x44BB8` | Paused draw timestamp: preserve `call [IAT]`; redirect its operand |
| D2Client RVA `0x44C00` | Client-loop clock: preserve `mov edi,[IAT]`; redirect its operand |
| `hooks.rs::update_game_time` | Select the precise non-SP clock only after the producer patches succeed |
| `hooks.rs::update_entity_positions` | Permit an extra half simulation interval for realm type 3 only when the correction is active |

The old D2Client IAT slot is RVA `0xCEF5C`; the new, already-existing `timeGetTime` slot is RVA `0xCF124`. Runtime addresses are computed from the actual module base. The configured game interval at RVA `0xF4318` must remain 40 ms.

The original negative-time clamp, subtraction of one interval, fixed-point fraction calculation, teleport/delta logic and post-draw restoration remain. For an ordinary 40 ms frame, the interpolation offset range is `[-40, 0]` ms in SP/LAN and `[-40, +20]` ms in corrected realm play. The positive part is bounded extrapolation; a sudden stop or turn may require a correction.

## Activation and guards

The module lives in `d2fps/src/mxl_timing.rs`. The existing D2GL `_Init@0` entry activates D2FPS normally.

The correction is considered only for 1.13c after D2FPS's motion-smoothing hooks succeed and only when `D2Sigma.dll` is loaded. It validates:

- D2Client file size and SHA-256, plus loaded x86 PE signature, timestamp and image size.
- The existing `timeGetTime` import and the 40 ms simulation interval.
- All four complete original instructions before any clock write.
- The readable committed code page and successful protection change before writing.
- Written bytes, instruction-cache flush and restoration of page protection.

All four sites share one code page. A failed preflight leaves them untouched; a failed write/readback or protection restoration attempts to restore the prior bytes and page protection. Guards are independent of the upstream `integrity-checks` setting. Disabling that setting does not bypass these checks.

When upstream reapplies its normal hooks at menu initialization, the clock module rechecks its four sites. It accepts only its exact installed operands or the exact originals, allowing known originals to be reapplied. Unknown code is never overwritten; a reapply conflict disables motion smoothing and is logged.

The initial instruction checks reject client clocks that were already changed, regardless of which module changed them. Reapplication accepts only the exact original or exact installed instructions. The D2Client identity guard remains in force.

## Scope

Other Diablo II versions and non-MXL installations retain upstream timing behavior. The four shared client timestamps also change in SP within an activated MXL setup; its interpolation limit remains original. The new bound applies only to `GameType::Bnet` (3), not TCP/IP or open Battle.net modes.

D2Net/D2Sigma code, simulation rate, packet contents, shaders and D2GL presentation are not changed by the new correction. This fork is a rebuild of public upstream and is not proven byte-equivalent to Median XL's signed D2FPS distribution. The timing behavior was verified at startup in the tested MXL installation. The cleaned build has passed native tests and a standalone loader check. See [validation](VALIDATION.md).
